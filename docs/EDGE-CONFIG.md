# Edge configuration (Cloudflare) — cache, security headers, redirects

GitHub Pages cannot set custom headers or server-side redirects, so these are
applied at the edge. Everything below assumes the domain is moved onto
Cloudflare (free plan is enough), with DNS proxying (orange cloud) enabled for
`magicmirrorbrooklyn.com` and `www`.

## 0. HTTPS first (owner action — blocks everything else)

1. In GitHub repo → Settings → Pages, confirm the custom domain and fix the
   apex A records (`185.199.108.153`–`111.153`, currently mistyped as `.53`).
2. Wait for the certificate to cover both hostnames, then enable
   **Enforce HTTPS**.
3. In Cloudflare: SSL/TLS mode **Full (strict)**, enable **Always Use HTTPS**.
4. Only after both apex and www serve valid HTTPS, enable HSTS (below).

## 1. Cache rules

Create two Cache Rules (Rules → Cache Rules):

| Rule | Match | Edge/Browser TTL |
|---|---|---|
| Immutable build assets | URI Path starts with `/_next/static/` | 1 year + `immutable` (assets are content-hashed) |
| Versioned media | URI Path starts with `/img/_r/` OR file extension in (webp, avif, mp4, woff2) | 30 days edge, 7 days browser |
| HTML (default) | everything else | respect origin (GitHub sends `max-age=600`) — fine, deploys propagate in ≤10 min |

Response header to add on the first rule: `Cache-Control: public, max-age=31536000, immutable`.

## 2. Security headers

Rules → Transform Rules → Modify Response Header, applied to all requests on
`www.magicmirrorbrooklyn.com`:

```
Strict-Transport-Security: max-age=31536000; includeSubDomains   (ONLY after step 0)
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()
X-Frame-Options: DENY
```

### Content-Security-Policy — start report-only

Origin inventory (current build):

- **Scripts/styles/fonts**: all self-hosted (`next/font` inlines Google fonts
  at build time — no runtime Google origin).
- **Images/video**: self only (`data:` used for placeholder pixels).
- **Form submissions (fetch)**: `https://formsubmit.co` today; add the lead
  Worker origin (e.g. `https://mmb-lead.<account>.workers.dev`) and/or the
  GoHighLevel webhook origin when configured.
- **Outbound links** (checkcherry booking, Instagram, Google reviews) do not
  need CSP entries.
- When analytics is added (GA4/Meta), extend `script-src` and `connect-src`
  accordingly before enforcing.

Deploy first as **Content-Security-Policy-Report-Only**:

```
Content-Security-Policy-Report-Only: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self'; font-src 'self'; connect-src 'self' https://formsubmit.co; form-action 'self' https://formsubmit.co; frame-ancestors 'none'; base-uri 'self'; object-src 'none'
```

Watch the console/reports for a week; when clean, rename the header to
`Content-Security-Policy`. (`'unsafe-inline'` for scripts is required by the
inline Next.js bootstrap and the chunk-reload guard; tightening to hashes is a
later optimization.)

## 3. Bulk redirects (legacy URLs → one-hop 301)

`docs/cloudflare-bulk-redirects.csv` (generated by
`node scripts/build-cloudflare-redirects.mjs`, 274 rules, verified chain- and
duplicate-free) is in Cloudflare's Bulk Redirect import format.

1. Cloudflare dashboard → Bulk Redirects → Create list → import the CSV.
   - Options per rule: **301**, "Preserve query string" OFF (legacy WP query
     params have no meaning on the new site), "Subpath matching" OFF.
2. Create the Bulk Redirect rule from the list and deploy.
3. For the old domain: keep `mirrormebrooklyn.com` DNS MX records untouched
   (email keeps working); point the web A/CNAME records at Cloudflare and let
   the same list redirect the mapped paths. Unmapped old-domain paths should
   fall back to a catch-all redirect to `https://www.magicmirrorbrooklyn.com/`
   (single Redirect Rule, lower priority than the list).
4. Verify with `node scripts/test-redirects.mjs` — it checks every source for
   a single-hop 301 to the exact mapped target and confirms each target
   returns 200.

The client-side `LegacyRedirect` component on the 404 page stays as a safety
net; it is not a substitute for these rules.

## 4. Lead Worker (when ready)

Deploy `workers/lead-worker.js` (`npx wrangler deploy`), set the secrets
listed in its header comment, then rebuild the site with
`NEXT_PUBLIC_LEAD_ENDPOINT=https://<worker-url>` so the form posts there.
No secret ever goes into `NEXT_PUBLIC_*`.
